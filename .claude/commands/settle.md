이 명령은 **깨끗한 컨텍스트**에서 실행되어야 효과가 있다(새 터미널 탭, 또는 /clear 직후). 이해부채 1건을 탑다운으로 정산한다.

원장 상태:
!`cat .claude/debt/pending.md 2>/dev/null || echo "(원장 없음)"`

대상 선택:
- 인자($ARGUMENTS)가 있으면 그에 가장 맞는 미정산(`- [ ]`) 항목.
- 없으면 `## 미정산` 의 가장 위(가장 오래된) 항목.

진행 규칙 — 엄수:
1. **탑다운으로 가르쳐라**: (a) 이 코드가 무엇을 하는지 → (b) 왜 이렇게 했는지 → (c) 밑바탕 원리·수학. 필요한 코드는 `git show` / Read / Grep 으로 직접 가져와 근거로 보여줘라.
2. 한 번에 다 쏟지 말고 **소크라테스식**으로: 한 단계 설명 후 짧은 확인 질문을 던져라. 사용자가 막히면 더 쉬운 비유로 내려가라("12살에게 설명하듯").
3. 사용자가 이해했다고 하면, **사용자에게 자기 말로 한 문단 요약을 직접 쓰게 하라**. 절대 네가 대신 요약을 써 주지 마라 — 이게 바이브코딩을 막는 핵심 장치다.
4. 사용자의 요약을 검증하라. 틀리거나 빠진 부분이 있으면 지적하고 2번으로 돌아가라.
5. 통과하면:
   - 사용자의 요약(그들의 표현 그대로)과 너의 교정 메모를 `.claude/notes/<주제-슬러그>.md` 에 추가하라.
   - `.claude/debt/pending.md` 에서 해당 항목을 `- [ ]` → `- [x]` 로 바꾸고 ` — settled <오늘 날짜>` 를 덧붙여 `## 정산 완료` 로 옮겨라.
6. 정산 도중 **코드 자체의 결함·개선점**을 발견하면 `.claude/debt/feedback.md` 에 `- [ ] <파일:줄> <문제> (from /settle <날짜>)` 로 적어라. 메인 세션이 다음 시작 때 이 목록을 보게 된다.
