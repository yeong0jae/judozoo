# 028 — 백엔드 Kotlin · Spring Boot 전환

Goal: 백엔드를 Python(FastAPI) → **Kotlin + Spring Boot + JPA**로 옮긴다. 운영을 멈추지 않고 **기능 단위로** 옮기며,
프런트엔드와 API 응답 모양은 바꾸지 않는다. 다 옮기면 FastAPI를 걷어낸다.

> 이유: 유지보수하는 사람이 Java·Kotlin·Spring에 익숙하다. Python 생태계를 계속 새로 배우는 비용을 없앤다.

### 공존 동안의 함정 — 먼저 막는다

- **세션 쿠키** — Kotlin이 Starlette 쿠키를 **읽을 수 있어야** 옮긴 화면에서 로그인이 유지된다.
  itsdangerous `TimestampSigner`(HMAC-SHA1, 키 파생) + base64 JSON을 Kotlin에서 검증한다. 로그인(발급)은 FastAPI에 끝까지 둔다.
  다 옮긴 뒤 Spring 세션으로 바꾸고 한 번 다시 로그인시킨다
- **브로커 토큰** — 키움은 앱키당 하루 1개, KIS는 1분 1회, 토스는 1개만 유효(`library/token_store.py`).
  두 프로세스가 각자 발급하면 서로를 무효화하거나 거부당한다. **브로커마다 발급 주인을 한 쪽으로** 정하고, 다른 쪽은 `broker_token` 테이블을 읽기만 한다
- **레이트 리미터** — 버킷이 프로세스 메모리에 있다(`library/rate_limiter.py`). 두 프로세스가 같은 브로커를 부르면 합이 한도를 넘는다.
  공존 동안 **한도를 두 쪽에 나눠 준다**(설정값). 한 브로커를 쓰는 기능이 다 옮겨지면 나누기를 걷는다
- **스케줄러** — 같은 작업이 두 쪽에서 돌면 안 된다. 기능을 옮기는 배포에서 Python `register`를 끄고 Kotlin `@Scheduled`를 켠다. 한 커밋에 둘 다
- **Python 쪽 코드는 바로 지우지 않는다** — 옮긴 기능이라도 남은 Python 기능이 그 `application`을 부르면 남겨 둔다. HTTP 경로와 스케줄만 넘어간다
- **메모리 캐시** — 주도주 후보 풀(10초 갱신)처럼 프로세스 메모리에 있는 상태를 아직 옮기지 않은 Python 기능이 읽으면,
  **양쪽이 각자 폴러로 채운다**(2026-10-16 결정). 브로커 조회가 그만큼 늘지만 나눠 받은 한도 안이다.
  **DB에 쓰는 작업**(분봉 정산·카탈로그 갱신 등)은 계속 한 쪽만 — 읽는 Python 기능이 다 옮겨질 때 넘긴다
- **메트릭 이름** — 대시보드가 FastAPI 계측 이름을 본다. Micrometer 이름을 맞추거나 패널을 두 쪽 다 그리게 고친다
- **오류 봉투** — `{code, status, data}` 모양과 코드 값(`UNAUTHORIZED`, `INTERNAL_ERROR`, `BET_REJECTED` …)을 그대로
