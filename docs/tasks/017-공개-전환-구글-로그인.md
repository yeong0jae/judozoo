# 017 — 공개 전환 + 구글 로그인

Goal: 개인용 IP 화이트리스트 서비스를 **누구나 접속 가능한 공개 서비스**로 전환한다. 공용 시세·분석 화면은 로그인 없이 열고, 주도주 실시간 로그만 구글 로그인 뒤에 둔다. 사용자가 공용 데이터를 바꿀 수 있는 경로는 전부 없앤다.

> 전제가 바뀌었다. `prd.md`는 "단일 사용자(개발자 본인), 다중 사용자·권한·계정 개념 없음"으로 쓰여 있고 데이터 모델이 실제로 그렇다 — `daily_issue`·`watch_theme`에 `user_id`가 없다. 이 phase는 **다중 사용자를 만들지 않는다.** 대신 사용자별 데이터를 쓰는 기능을 제거해서 그 문제 자체를 없앤다.

## 진입 조건 (현재 상태)

- `https://judozoo.com` HTTPS 적용 완료 ([016](016-도메인-https.md))
- 방화벽이 tcp 80·443을 **개인 IP 6개**에만 개방
- 인증 장치 **0개** — `Depends`는 전부 `get_db`
- 쓰기 엔드포인트 11개가 무인증으로 열려 있음
- TTL 캐시가 프로세스 전역 — 같은 데이터를 보는 사용자가 늘어도 브로커 호출은 안 늘어난다

## 설계 결정

| 항목 | 선택 | 이유 |
|---|---|---|
| 사용자별 데이터 | **기능 제거** | `user_id` 스키마 변경·마이그레이션·쿼리 수정 전부를 회피한다 |
| 인증 방식 | 구글 OAuth (Authorization Code) | client secret이 브라우저로 나가지 않는다 |
| 세션 | **서명 쿠키** (Starlette `SessionMiddleware`) | 프론트·API가 같은 오리진이라 쿠키가 그냥 붙는다. JWT는 서비스가 하나인 여기서 이점이 없고 로그아웃만 어려워진다 |
| 로그인 대상 | **아무나** (구글 계정 보유자) | 접근 통제가 아니라 가입 유도. 홍보가 목적 |
| 게이트 범위 | 실시간 로그 2개 엔드포인트만 | 나머지는 전부 공개 |

## 2. 구글 OAuth 클라이언트

> **동의 화면은 두 단계로 간다.** 대상은 **외부**를 고르되, 처음엔 구글이 자동으로 "테스트" 모드에 둔다.
> 테스트 모드에서는 **등록한 테스트 사용자(최대 100명)만** 로그인된다. 구현·검증은 이 상태로 하고,
> **프로덕션 게시는 §8 직전**에 한다. 게시를 빠뜨리면 홍보해도 아무도 로그인하지 못한다.
>
> 내부(Internal)는 Google Workspace 조직 전용이라 목적과 반대다.

- [x] OAuth 동의 화면 — 대상 **외부** 선택, 앱 이름·지원 이메일 입력
- [x] 범위는 `openid`, `email`만. 민감 범위를 넣으면 구글 심사가 붙는다
- [x] 테스트 사용자에 본인 계정 추가 (이 단계에선 이 계정만 로그인된다)
- [x] 사용자 인증 정보 → OAuth 클라이언트 ID (웹 애플리케이션) 생성
- [x] 승인된 리디렉션 URI: `https://judozoo.com/api/auth/callback`
- [x] 시크릿 3개 추가 → `terraform apply` → 값 주입
      (`AT_GOOGLE_CLIENT_ID`, `AT_GOOGLE_CLIENT_SECRET`, `AT_SESSION_SECRET`)
- [x] `remote_deploy.sh`가 셋을 `secrets/.env`에 기록

## 6. 남용 방지

> 읽기 전용이어도 트래픽은 비용이다. 특히 종목별 엔드포인트는 종목 코드로 캐시 키가 갈려서, 서로 다른 종목을 대량 조회하면 캐시가 밀리며 브로커 호출이 선형 증가한다.

- [x] 브로커 RateLimiter 동작 확인 — **거부가 아니라 최대 20초 대기**한다
- [x] `frontend/nginx.conf`에 `limit_req` — `/api/` 대상 10r/s, burst 20, 429
- [x] **`set_real_ip_from` + `real_ip_header`** — nginx가 Caddy 뒤라 복원하지 않으면 모든 방문자가 Caddy IP 하나로 묶여 서로를 밀어낸다
- [x] **`/health`를 `async def`로** — sync면 스레드풀을 쓰는데, 브로커 대기로 풀이 고갈되면 헬스체크까지 멈춰 배포·재시작 판단이 오염된다

> **연쇄 실패 경로를 먼저 확인했다.** 브로커 호출 엔드포인트가 전부 sync(`def`)라 스레드풀(40)을
> 점유하고, 공유 RateLimiter는 거부 대신 20초를 기다린다. 서로 다른 종목을 보는 방문자가 40명만
> 동시에 들어와도 풀이 고갈되고, 그때부터는 캐시로 답할 공개 화면과 `/health`까지 같이 멈춘다.
> `limit_req`는 그 상황을 만들지 않기 위한 것이고, `/health` async는 그럼에도 벌어졌을 때
> 헬스체크만은 살리기 위한 것이다.
>
> **RateLimiter 타임아웃(20초)은 건드리지 않았다.** 폴러와 사용자 요청이 같은 리미터를 공유해서,
> 낮추면 폴러 동작이 함께 바뀐다. 위 두 조치로 먼저 막는다.

## 알려진 함정

- **`/health`·`/health/db`를 막으면 배포가 깨진다.** compose 헬스체크와 `remote_deploy.sh`가 둘 다 쓴다.
- **배포 헬스체크는 `https://judozoo.com/`를 친다.** 루트가 미로그인 200을 유지해야 한다 — 전체를 로그인 뒤로 넣으면 배포가 실패한다.
- **ID 토큰 검증을 생략하면 안 된다.** 서명·`aud`·`iss`·만료를 전부 본다. 검증 없는 디코딩은 인증이 아니다.
- **`state` 없이 콜백을 처리하면 CSRF에 열린다.**
- **`AT_SESSION_SECRET`이 바뀌면 모든 세션이 무효화된다.** 재발급 시 전원 재로그인.
- **동의 화면이 테스트 모드면 등록된 테스트 사용자만 로그인된다.** 구현이 멀쩡해도 남들은 거부당한다 — 증상이 "내 계정으로는 되는데 친구는 안 됨"으로 나타난다.
- **비민감 범위(`openid`·`email`)만 쓰면 구글 앱 심사는 통상 불필요하다.** 다만 로고·홈페이지·개인정보처리방침 URL을 안 채우면 로그인 시 "확인되지 않은 앱" 경고가 뜬다 — §7에서 만든 처리방침 URL을 연결한다.
- **방화벽 규칙은 OR로 평가된다.** 우리 규칙을 좁혀도 더 넓은 규칙이 하나라도 있으면 그쪽이 이긴다. GCP의 `default-allow-ssh`가 정확히 그랬다 — 타깃 태그가 없어 모든 VM에 적용된다.
- **`allowed_web_source_ranges`를 SSH 규칙과 공유하면 안 된다.** 앱을 공개하는 순간 SSH까지 열린다.
- **화이트리스트를 걷으면 오리진 IP가 그대로 노출된다.** 그 시점부터 Cloudflare 프록시(주황 구름)를 켜는 게 실익이 있다 — DDoS 보호와 오리진 은닉. DNS-01이라 인증서 발급은 그대로 동작한다. 대신 Cloudflare가 TLS를 종단하니 평문 트래픽을 보게 된다.

## 후속

- **종목별 캐시 `maxsize` 조정** — `stockNews`·`stockInvestorDaily`가 100이라, 서로 다른 종목 101개가
  조회되면 밀려난 종목이 브로커를 다시 친다. 다만 방문자 규모를 모르는 상태에서 키우면 메모리만 먹는다.
  Grafana에서 캐시 적중률·브로커 호출량을 본 뒤 정한다
- RateLimiter를 폴러용·사용자용으로 분리할지 검토 (지금은 공유라 타임아웃을 못 낮춘다)
- Cloudflare 프록시 전환 검토 (위 함정 마지막 항목)
- 접속 지표 — Grafana에 가입자 수·DAU 패널
- MySQL 백업 — 공개 서비스가 되면 `app_user`와 스냅샷 데이터가 유실되면 안 된다. 현재 백업 없음
- 인스턴스 규모 — e2-medium 1대에 MySQL 동거. 트래픽이 붙으면 분리 검토
