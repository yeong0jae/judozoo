# PRD: 주도주 자동 트레이딩 시스템

## 개요

사용자가 주도주를 선정하여 시스템에 명령하면, 시스템이 정해진 기준에 따라 자동으로 매매하고 결과를 리포트로 제공하는 자동 트레이딩 시스템.

---

## 플로우

```
사용자: 주도주 선정 → 종목명 + 1회 매수 금액 입력 (+ 선택적 룰 파라미터)
     ↓
시스템: 사전 정의된 기준에 따라 자동 매매 실행
     ↓
결과: 매매 결과 리포트 출력
```

---

## 거래 환경

- **실거래 전용** — 실제 증권사 계좌, 실제 자금으로 운용
- 모의투자 / 백테스트 모드는 본 PRD 범위에 포함하지 않음
- **모든 매매 룰의 단위 테스트 / 통합 테스트로 검증 필수** (실거래에서 룰 버그는 즉시 손실로 직결)
- **시스템 다운/재시작**: 진행 중인 명령(INITIATED/BUYING/MONITORING/LIQUIDATING)은 재시작 시 자동으로 close_reason = `UNCLOSED`로 마감. 사용자 별도 조치 불필요 — 모니터링 화면 "오늘 종료" 섹션과 실적 화면에 UNCLOSED 행으로 자연스럽게 노출됨

### 증권사 연동

- **한국투자증권 KIS Developers** API 사용
- **REST API**: 주문 (매수/매도), 잔고/체결 조회, 시세 조회
- **WebSocket**: 실시간 시세 및 체결 통보 수신. 끊김 시 자동 재연결 시도 + 재연결 완료 전까지 REST 폴링으로 시세 감지 유지
- **인증**: OAuth2 (AppKey + AppSecret으로 액세스 토큰 발급, 만료 시 재발급)
- 추후 결정 사항:
  - 인증 키 보관 방식 (환경변수 / DB 암호화 / 시크릿 저장소)

## 매매 명령

### 취소 처리

- 매수 진행 중 취소 시 — 추가 매수 즉시 중단 + 보유 수량 **시장가 전량 매도** 후 명령 종료
- 취소는 매매 사이클 전체를 종료 (익절/손절 룰 이어가지 않음)
- 매도 실패 시 5초 간격 무제한 재시도 (체결 완료까지)
- **in-flight 매수 주문이 있을 때 취소**: KIS API로 해당 주문 취소 시도 → 취소 성공 시 잔여 보유 수량만 매도, 취소 실패(이미 체결) 시 체결 수량 포함 전량 매도
- **보유 수량 = 0 상태에서 취소 시**: 매도할 포지션이 없으므로 Liquidating 거치지 않고 즉시 종료 (close_reason = `CANCELLED`)
- **이미 청산 진행 중(LIQUIDATING) 상태에서 재취소**: 멱등 처리. 진행 중인 청산을 그대로 둠
- **이미 종료된(CLOSED) 명령에 취소 시도**: 거부 (errorCode = `ALREADY_CLOSED`)

### 중복 명령 처리

- 진행 중인 종목에 새 명령이 들어오면 **거부** (에러 메시지 표시)
- 기존 명령이 완전 청산(익절/손절/본전 매도/장마감 강제 청산)된 후에만 같은 종목 재명령 가능
- 한 종목 = 한 매매 사이클 원칙
- **다중 종목 동시 운용**: 종목 수 제한 없음. 잔고가 허용하는 만큼 동시 명령 가능

### 명령 가능 시간

- **거래일 확인**: 앱 시작 시 KIS API 영업일 조회로 당일 거래 가능 여부 확인. 휴장일이면 명령 접수 전체 차단
- 정규장 시간 내(09:00 ~ 15:30) 명령 가능
- 단, **신규 명령 컷오프 시각** = `15:20 - (추가 매수 간격 × 2)`
  - 기본 3분 간격: **15:14까지** 명령 가능
  - 5분 간격: **15:10까지** 명령 가능
- 컷오프 이후 신규 명령은 거부 (UI에서 에러 메시지)
- 이유: 3회 매수가 강제 청산 시각(15:20) 전에 안정적으로 완료되도록 보장

### 입력값

| 항목 | 설명 | 기본값 | 허용 범위 |
|------|------|--------|----------|
| 종목명 | 매수할 종목 (검색 지원) | - | - |
| 1회 매수 금액 | 회당 매수 금액 (원 단위) | - | 10,000원 이상 **AND** 현재가 기준 1주 가격 이상 (둘 중 큰 값이 실질 하한) |
| 추가 매수 간격 | 1회 매수 후 추가 매수 대기 시간 (분) | 3분 | 1분 ~ 30분 |
| 분할 매도 비율 | 목표 익절 시 1회당 매도 비율 | 20% | 10% ~ 30% |
| 중도 익절 기준 수익률 | 매수 미완료 시 익절 전환 수익률 | 3% | 0.1% ~ 10% |
| 본전 매도 기준 수익률 | 본전 매도 발동 전 최소 상승 수익률 | 2% | 0.1% ~ 10% |
| 손절 기준 손실률 | 손절 발동 손실률 | -2% | -0.1% ~ -10% |

> **1회 매수 금액 검증**: 명령 접수 시 KIS API로 현재가를 조회하여 1주 가격보다 낮으면 즉시 거부 (에러 메시지 표시)

> **잔고 검증**: 명령 접수 시 `1회 매수 금액 × 3`을 충당할 잔고가 있는지 확인. 이미 진행 중인 다른 종목 명령의 예약 금액도 차감하여 계산. 잔고 부족 시 즉시 거부 (에러 메시지 표시)

### 거부 사유 (요약)

본문 곳곳에 흩어진 거부 케이스를 한눈에 매핑하기 위한 인덱스. spec의 `errorCode`와 1:1 대응.

| 거부 사유 | 발동 조건 | errorCode |
|----------|----------|-----------|
| 종목 미발견 | KIS 종목 검색 실패 | `STOCK_NOT_FOUND` |
| 1주 가격 미만 | 1회 매수 금액 < 현재가 | `PRICE_BELOW_ONE_SHARE` |
| 잔고 부족 | 가용 잔고 < (1회 매수 금액 × 3), 다른 활성 명령 예약분 차감 후 | `INSUFFICIENT_BALANCE` |
| 중복 명령 | 같은 종목에 활성 명령(INITIATED/BUYING/MONITORING/LIQUIDATING) 존재 | `DUPLICATE_COMMAND` |
| 컷오프 도달 | 현재 KST 시각 ≥ 15:20 − (추가 매수 간격 × 2) | `CUTOFF_PASSED` |
| 휴장일 | 당일 영업일 아님 | `HOLIDAY` |
| 정규장 시간 외 | 09:00 이전 또는 15:30 이후 | `OUT_OF_TRADING_HOURS` |
| 입력값 범위 외 | 입력값 표의 허용 범위 위반 | `INVALID_PARAMETER` |

## 시스템 매매 규칙

### 1. 매수

- 명령 검증 통과 직후 BUYING 상태 진입 + 1차 매수 시도 발송 (발송 성공/실패 무관하게 BUYING 진입)
- 이후 **사용자 설정 간격**(기본 3분)으로 2회 추가 매수 (총 3회)
- **주문 유형: 시장가** (모든 매수 회차)
- **회차별 발송 실패 처리**: 해당 회차 스킵, 다음 회차는 예정 시각에 정상 시도 (재시도 없음). 1차가 실패해도 BUYING 유지하며 2/3차 시도를 기다림.
- **부분 체결 / 미체결 처리**: 회차별로 시장가 주문 후 부분 체결분은 보유하고 미체결 잔량만 즉시 취소.
  다음 회차는 예정된 시각에 새 시장가 주문으로 정상 진행 (잔량 누적·재시도 없음).
  → 총 매수액이 의도(1회 매수 금액 × 3)보다 적을 수 있으나, 익절/손절은 비율 기반이므로 정상 동작.
- **3회 매수 시도 완료 후 보유 수량 = 0인 경우**: 매도할 포지션이 없으므로 사이클 즉시 종료. close_reason = `NO_FILL`로 리포트에 표시.

### 2. 목표 익절

**3회 매수 시도가 완료된 후** 발동 (체결 여부와 무관하게 3회 주문 시도를 완료한 시점 기준). 총 매수 수량을 **사용자 설정 비율**(기본 1/5)로 분할 매도:

| 조건 | 매도 수량 |
|------|----------|
| 수익률 +2% 도달 | 총 수량의 N% (설정값) |
| 수익률 +3% 도달 | 총 수량의 N% |
| 수익률 +5% 도달 | 총 수량의 N% |
| 나머지 수량 | 추세 꺾임 OR 상한가 도달 — **둘 중 먼저 발생한 이벤트** 시점에 전량 시장가 매도 |

> **매도 수량 계산**: 소수점 이하 절사, 나머지는 마지막 매도에 포함

> **갭상승 / 급등으로 복수 단계 동시 충족 시**: 충족된 모든 단계를 한 번에 발동하여 합산 비율로 매도.
> 예) 시초가가 +6%로 시작하면 2%/3%/5% 단계가 모두 충족 → 분할 비율 20% × 3단계 = **60% 즉시 매도**

**예시 (기본값 20%, 총 100주 매수 시)**
- 2% 수익 → 20주 매도
- 3% 수익 → 20주 매도
- 5% 수익 → 20주 매도
- 잔여 40주 → 추세 꺾임 또는 상한가 시 전량 매도

### 3. 중도 익절

3회 매수 완료 전, **수익률 +N% 이상**(기본 3%, = 중도 익절 기준 수익률) 달성 시:
- 추가 매수 중단
- **그 시점까지 보유한 수량**을 기준으로 §2 목표 익절 룰을 그대로 적용. 충족된 모든 단계는 §2의 "복수 단계 동시 충족 시 합산 매도" 룰에 따라 한 번에 매도 (예: 매수 2회차 직후 +3.5%에서 발동 시 2%·3% 단계 합산 40% 즉시 매도, +5%·추세 꺾임·상한가는 그대로 대기)
- 발동 이후 본전 매도(§4) / 추세 꺾임 / 손절(§5) / 장 마감(§6)은 §2 Holding 상태와 동일하게 활성
- 중도 익절 기준 수익률(+N%) **미만**에서는 익절 발동하지 않고 정상적으로 추가 매수 진행

### 4. 본전 매도

**분할 매도 단계 진입 후**(3회 매수 시도 완료 §2, 또는 중도 익절 발동 §3), 매수가 대비 **+N% 이상 상승**(기본 2%) 후 **현재가 ≤ 매수가** 도달 시:
- 보유 수량 전량 **시장가 매도**

> **"매수가" 정의**: 매수 원가 + 예상 매도 비용까지 반영한 손익 0 기준가. 산식은 [매수가 산정](#매수가-산정) 참고. 본 트리거는 그 가격 도달 시점이므로 발동 시 (예상 비용 정확도 범위 내에서) 손익 0 보장.

### 5. 손절

3회 매수 완료 또는 매수 진행 중, 매수가 대비 **-N% 하락**(기본 -2%) 시:
- 추가 매수 없이 전량 **시장가 매도**

> **익절/손절 동시 충족 시**: 손절 우선 발동. 손절 = 전량 청산이므로 이후 모든 시그널 자동 소멸.

### 6. 장 마감 정책 (수동 청산)

- 자동 강제 청산 없음. 장 마감(15:30) 시점에 미청산 보유분이 있어도 시스템이 자동 매도하지 않음.
- 사용자가 직접 청산하거나 다음 영업일로 이월 — 두 선택지 모두 허용.
- 다만 컷오프 정책(`15:20 - buyIntervalMin × 2`)은 유지 — 새 사이클이 마감 전 매수 시퀀스를 완주할 수 없는 시각엔 신규 명령을 차단.

### 7. 시장 안전장치(VI / 거래정지 / 호가공백) 처리

시스템은 VI, 거래정지, 상한가 호가공백 등을 별도로 감지하지 않고, **주문 결과(성공/실패)만 보고 동작**한다.

- **매수 회차 주문 실패 시**: 해당 회차는 **스킵**, 다음 회차는 예정 시각에 정상 시도 (재시도 없음)
- **매도 주문 실패 시** 시그널 유형별 재시도 정책:
  - **손절 / 취소 시 매도**: 한 번 발동하면 체결 완료까지 **5초 간격 무제한 재시도** (가격 회복과 무관)
  - **본전 매도**: 현재가 ≤ 매수가 조건이 유지되는 동안 재시도. 가격이 매수가 위로 회복되면 재시도 중단 (조건 재충족 시 재발동)
  - **추세 꺾임**: 해당 3분봉에서 조건이 유지되는 동안 재시도. 다음 봉에서 조건 해소 시 중단 (이후 재충족 시 재발동)
  - **장 마감 강제 청산 / 목표 익절 분할 매도**: 해당 시그널 해소 없이 체결 완료까지 무제한 재시도
  - 거래정지가 길어져 장 마감까지 청산 못 한 경우 — 미청산 종목(close_reason=UNCLOSED)으로 리포트에 표시. 다음 영업일 처리는 사용자가 수동으로 결정
- **주문 타임아웃 시**: 단순화 — 별도 reconcile(KIS 체결 내역 조회) 없이 응답이 안 오면 실패로 간주. 매도 재시도 정책에 따라 다시 발사. 드물게 KIS는 처리됐으나 응답 손실 → 중복 주문 가능성 존재 (운영 중 발생 시 수동 정리).
- 주문 실패는 모두 로그로 기록

## 주요 산식 및 기준

### 시그널 평가 전제

가격 기반 시그널(StopLoss / MidwayTakeProfit / TpStage / Breakeven / TrendBreak)은 **보유 수량 > 0 + 매수가 산출 가능** 상태에서만 평가한다.

- 매수 1차 미체결 등으로 보유 수량 = 0인 동안에는 매수가 자체가 정의되지 않으므로 모든 가격 기반 시그널 평가 보류
- 첫 부분 체결 발생 시점부터 시그널 평가 시작
- MarketClose / Cancel은 보유 수량과 무관하게 평가 (보유 = 0이면 매도 없이 즉시 Closed로 종료)

### 추세 꺾임 판단

```
3분봉 기준: 0봉(현재봉)의 현재가 < 1전봉의 시가
```

- 조건: 매수가 대비 **+5% 이상 상승 후** 위 조건 충족 시 추세 꺾임으로 판단
- **3분봉 고정** — 사용자가 설정하는 "추가 매수 간격"과 무관 (분할 매수 타이밍과 정점 감지는 별개의 시간 축)
- KIS API의 3분봉 응답을 그대로 사용
- **데이터 부족 처리**: 1전봉이 존재하지 않는 경우(장 시작 후 첫 3분) 추세 꺾임 판정 보류 — 상한가 도달 또는 이후 봉에서 조건 충족 시까지 잔여 수량 보유

### 매수가 산정

```
매수 원가평균 = (Σ(매수가격 × 매수수량) + Σ매수 수수료) / 총 매수수량
매수가 = 매수 원가평균 × (1 + 매도 비용률)
```

- **정의**: 매수 시 비용과 매도 시 예상 비용을 모두 반영한 **"매도 후 손익 0이 되는 가격"**. 모든 룰(익절·손절·본전 매도·추세 꺾임)이 이 매수가를 단일 기준으로 사용.
- **매도 비용률**: 시스템 설정값. 기본 **0.25%** (한국 주식 매도 거래세 0.18% + 매도 수수료 약 0.02% + 버퍼). 세제·증권사 변경 시 설정만 조정.
- 한국 주식은 매수 시 거래세가 부과되지 않으므로 원가평균에는 매수 수수료만 포함.
- KIS API의 "평균매입단가"(원가 기준)와는 다른 값. spec/UI에서 두 값을 구분 명시.

## 화면 구성

### 매매 명령 화면

새 매매 명령을 접수하는 화면. PRD §매매 명령의 "입력값" 7개 필드를 모두 입력하고, 명령 접수 검증(잔고 / 1주 가격 / 컷오프 / 휴장일)에 필요한 컨텍스트를 함께 노출한다.

#### 입력 필드

| 항목 | 기본값 | 비고 |
|------|--------|------|
| 종목명 | - | 종목명 검색 자동완성 (코드/이름) |
| 1회 매수 금액 | - | 원 단위 |
| 추가 매수 간격 | 3분 | |
| 분할 매도 비율 | 20% | |
| 중도 익절 기준 수익률 | 3% | |
| 본전 매도 기준 수익률 | 2% | |
| 손절 기준 손실률 | -2% | |

> 추가 매수 간격 ~ 손절 기준의 5개 룰 파라미터는 **"고급 설정"으로 접어 두고**, 기본값으로 명령을 접수할 수 있도록 한다. 사용자가 명시적으로 펼쳐서 수정 시에만 변경된 값으로 전송.

#### 표시 정보 (검증 컨텍스트)

- **사용 가능한 잔고**: 현재 가용 잔고 (이미 진행 중인 명령의 예약 금액 차감 후). 다른 명령의 생성/종료 이벤트 발생 시 자동 갱신.
- **선택 종목 현재가**: 종목 선택 시 자동 표시
- **예상 매수 수량**: `1회 매수 금액 / 현재가` (소수점 절사)
- **예상 총 매수 금액**: `1회 매수 금액 × 3` — 잔고 검증 기준
- **명령 가능 여부**: 휴장일 / 컷오프 도달 시 비활성화 + 사유 표시

#### 액션

- **매수 명령 전송**: 검증 통과 시 명령 접수 → 진행 중 모니터링 화면으로 자동 이동
- 검증 실패 시 거부 사유 표시 (PRD §매매 명령의 거부 케이스: 1주 가격 미만 / 잔고 부족 / 중복 명령 / 컷오프 / 휴장일)

### 진행 중 모니터링 화면

명령 접수 후 청산되기 전까지의 활성 사이클을 추적하는 화면. 다중 종목 동시 운용을 지원하므로, **활성 명령 리스트 뷰**와 선택 시 **단일 명령 상세 뷰**가 결합된 형태로 구성한다.

**진입 시점**: 명령 접수 직후 ~ 사이클 종료 시까지.

#### 리스트 뷰 (활성 명령 전체)

활성 상태(INITIATED / BUYING / MONITORING / LIQUIDATING)에 있는 모든 명령을 한 행씩 요약 표시. 행 클릭 시 해당 명령의 상세 뷰로 진입.

| 항목 | 설명 |
|------|------|
| 종목명 | |
| 명령 상태 | 배지 |
| 수익률 / 평가손익 | 실시간 |
| 매수 회차 | 1/3, 2/3, 3/3 |
| 보유 수량 | |

리스트 상단에 **시스템 상태 배지**를 전역 표시. 사용자가 "어디를 봐야 하지" 헤매지 않도록 시스템 전역 상태를 한 자리에서 노출:

| 상태 | 표시 | 의미 |
|------|------|------|
| 시세 모드 | `정상 WS` / `폴링 모드` | 폴링 모드는 시그널 발동이 최대 1초 지연 가능 — 배지 hover 시 안내 표시 |
| KIS 토큰 | `정상` / `갱신 실패` | 갱신 실패 시 신규 명령 / 신규 주문 차단 — 빨간색 강조 |
| 거래일 | (정상 시 미표시) / `휴장일` | 휴장일이면 신규 명령 접수 전체 차단 |

#### 상세 뷰 (선택된 단일 명령)

##### 표시 항목

| 분류 | 항목 | 설명 |
|------|------|------|
| 식별 | 종목명 / 명령 상태 | INITIATED / BUYING / MONITORING / LIQUIDATING |
| 포지션 | 평균 매수가 / 현재가 | 가중평균 매수가 (수수료/세금 포함) |
| 포지션 | 수익률 / 평가손익 | (현재가 - 매수가) / 매수가, 원 단위 손익 |
| 포지션 | 보유 수량 | |
| 매수 진행 | 매수 회차 | 1/3, 2/3, 3/3 |
| 시그널 | 목표 익절 단계 | 2% / 3% / 5% 각 단계 발동 여부 |
| 시그널 | 분할 매도 진행도 | 매도된 비율 (예: 60% / 100%) |
| 시그널 | 본전 매도 무장 여부 | 매수가 대비 +N% 도달 시 무장 |
| 시그널 | 추세 꺾임 무장 여부 | 매수가 대비 +5% 도달 시 무장 |
| 운영 | 매도 재시도 상태 | LIQUIDATING 상태에서만 표시: 진행 중 매도 시그널 + 누적 재시도 횟수 + 마지막 에러 메시지 (3회 이상 실패 시 강조) |
| 액션 | 취소 버튼 | 진행 중 사이클 즉시 청산 (시장가 전량 매도) — **확인 다이얼로그 필수** |

> **취소 위치 제한**: 취소 버튼은 **상세 뷰에서만 노출**. 리스트 행에는 두지 않는다. 이유: 취소 = 시장가 전량 매도 = 즉시 손실 확정 가능 → 오클릭 위험을 줄이기 위해 상세 뷰 진입(1단계) + 확인 다이얼로그(2단계)의 안전망을 둔다.

##### 상태별 노출 규칙

- **BUYING**: 매수 회차 진행도 강조. 시그널 항목은 "중도 익절"만 활성, 그 외는 비활성 회색 처리.
- **MONITORING**: 시그널 항목 전부 활성. 매수 회차는 "3/3 완료" 고정.
- **LIQUIDATING**: 청산 사유 + 매도 진행 표시. 다른 시그널 항목 비활성.

#### 갱신 방식

- 시세(현재가 / 수익률 / 평가손익): 실시간 푸시 — 리스트 / 상세 모두 적용
- 상태 전이(매수 체결, 시그널 발동/무장, 매도 재시도 누적): 이벤트 푸시
- 시스템 상태 배지: 시스템 전역 상태(시세 모드 / 토큰 / 휴장 / UNCLOSED 카운트) 변경 시 푸시

#### 종료 인지 (알림 채널 부재 보완)

알림 채널이 v1에 없으므로, 명령 종료(특히 사용자 능동 행위 없이 종료된 NO_FILL / STOP_LOSS / MARKET_CLOSE 등)가 모니터링 리스트에서 즉시 사라지면 사용자가 인지하기 어렵다. 보완책:

- **종료 토스트**: 모니터링 페이지에 사용자가 머무는 동안 lifecycle CLOSED 이벤트 도착 시 한 번 토스트 표시 (예: "삼성전자 명령 종료 — NO_FILL"). 알림 채널이 아닌 화면 내 1회 표시.
- **"오늘 종료" 미니 섹션**: 모니터링 화면 하단에 오늘 종료된 모든 명령 리스트(종목 / close_reason / 수익률) 요약 표시. **재시작으로 인한 UNCLOSED 명령도 여기에 함께 노출** — 사용자가 별도로 어딜 봐야 할지 헷갈릴 일 없음. 클릭 시 실적 화면으로 이동.

### 실적 조회 화면

| 항목 | 설명 |
|------|------|
| 일자 | 매매 일자 |
| 종목명 | 매매 종목 |
| 매수금액 | 총 매수 금액 |
| 매도금액 | 총 매도 금액 |
| 수수료 | 거래 수수료 |
| 세금 | 거래세 |
| 수익금 | 순 수익 금액 |
| 수익률 | 수익 퍼센트 |
| 청산 사유 | TAKE_PROFIT / STOP_LOSS / BREAKEVEN / TREND_BREAK / MARKET_CLOSE / CANCELLED / NO_FILL / **UNCLOSED** |

> **UNCLOSED 행 표시**: 시스템 다운/재시작으로 인해 종료된 명령(거래 환경 §시스템 다운 참고) 또는 거래정지로 장 마감까지 청산되지 못한 명령은 청산 사유 = `UNCLOSED`로 표시. 거래정지 케이스는 §시스템 매매 §7에 따라 KIS에서 수동 정리 필요, 시스템 다운 케이스는 별도 조치 불필요.

> **개발 우선순위**: 일별 실적 우선 개발, 월별 실적은 트레이딩 성과에 따라 추후 개발

> **데이터 저장소**: MySQL. 거래 내역 및 명령 상태를 영속화
