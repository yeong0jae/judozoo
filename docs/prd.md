# PRD: judozoo — 주도주 판단 보조 서비스

## 개요

단타 매매 판단에 필요한 데이터를 여러 소스에서 모아 **가공·전시**하는 공개 웹 서비스. `https://judozoo.com`

사용자는 이 화면들을 보고 "지금 무엇을 볼 것인가"를 판단한다. **주문은 시스템이 내지 않는다.** 매수·매도는 사용자가 증권사 HTS/MTS에서 직접 한다.

> **이력**
> - 자동 매매 시스템으로 출발했다(명령 접수 → 자동 주문 → 실적 리포트). "룰이 사람의 판단을 대체하기 어렵다"는 결론으로 **판단 보조**로 전환했고, 주문·체결 코드는 전부 제거했다. 과거 설계는 `tasks/000` ~ `tasks/013`에 이력으로 남아 있다.
> - 개발자 본인만 쓰는 IP 허용목록 서비스였다가 [017](./tasks/017-공개-전환-구글-로그인.md)에서 **누구나 접속하는 공개 서비스**로 바꿨다. 이때 사용자별 데이터를 쓰는 기능(이슈 메모·관심 테마)은 제거했다.

---

## 해결하려는 문제

장중에 판단 근거가 되는 데이터는 여러 곳에 흩어져 있다.

- 거래대금 상위, 등락률, 분봉 거래대금 급증 — HTS 조건검색
- 투자자 수급 — 별도 화면
- 선물·해외 지수·환율 — 또 다른 창
- 뉴스·공시 — 브라우저

장중에 이걸 창을 옮겨 다니며 조합하면 **판단 시점을 놓친다.** 이 서비스는 흩어진 데이터를 한 화면에 정렬해 그 시간을 없앤다. 여기에 더해, 장을 보지 못한 시간에 **무엇이 주도주였고 어떻게 바뀌었는지**를 되짚을 수 있게 기록을 남긴다.

## 기능 요구사항

### 1. 주도주 후보와 첫 화면 주도주

**후보 목록**은 거래대금 상위 풀에서 두 기준만 통과한 종목이다.

| 필터 | 기준 (기본값) |
|------|--------------|
| 거래대금 순위 | 상위 35위 이내 |
| 당일 등락률 | +7% 이상 — 사용자가 화면에서 -12% ~ +7% 사이로 조정 |
| ETF/ETN · 스팩 | 제외 |

**첫 화면 주도주**는 후보 풀(등락률 0% 이상)에서 **거래대금과 등락률이 함께 높은** 상위 5종목이다. 사용자가 후보 목록에 건 등락률과 무관하게 누구에게나 같은 답을 보여준다. 같은 풀에서 **상한가** 종목을 칩으로 함께 보여준다. 풀이 거래대금 35위까지이므로 시장 전체의 상한가는 아니다.

**종목 상세**는 전체 필터를 평가해 **어느 기준을 통과하고 어디서 떨어졌는지**를 보여준다.

| 필터 | 기준 (기본값) | 의미 |
|------|--------------|------|
| 거래대금 순위 | 35위 이내 | 주도주 정의 |
| 당일 등락률 | +7% 이상 | 주도주 정의 |
| 최근 고가 대비 | 60봉 고가 대비 -5% 이내 | 지금 들어갈 자리인가 |
| 시가 위 | 현재가 > 시가 | 지금 들어갈 자리인가 |
| 전일 등락률 | +25% 이하 | 이미 다 간 종목 배제 |
| 시초가 대비 | +7% 이하 | 이미 다 간 종목 배제 |
| 시가총액 | 3,000억원 이상 | 느슨한 하한 |
| 프로그램 양매수 | 순매수 | 느슨한 하한 |

- 기준값은 환경변수로 조정할 수 있어야 한다
- 상세에는 상대거래량, 1분봉·일봉 차트가 함께 나온다

**해외(미국)** 도 같은 구조다. 나스닥·뉴욕·아멕스를 합친 거래대금 상위 40에서 등락률 기준(기본 +5%)으로 후보를 뽑고, 상세에서 시가총액($2B 이상)까지 평가한다. ETF는 영문명 키워드로 거른다.

### 2. 주도주 기록 — 타임라인과 캘린더

주도주를 새로 정의하지 않는다. **첫 화면 주도주 카드가 고른 5종목을 기록할 뿐이다.**

| 기록 | 주기 | 시간대 |
|------|------|--------|
| 타임라인 | 매분 | 국내 08:00~20:00 KST, 해외 04:00~20:00 뉴욕 (마감 분 포함) |
| 캘린더 | 하루 1회 | 국내 20:01 KST (애프터마켓 마감 후), 해외 16:01 뉴욕 (정규장 마감) |

- 국내는 08:50~09:00, 15:30~15:40(장 전환 구간)을 찍지 않는다
- 캘린더는 "주도주 없음", "휴장", "기록 없음"을 구분해 보여줘야 한다
- 캘린더의 한 날짜 칸에는 그날 국내장과 **직전 평일 해외장**을 함께 둔다
- 기록은 서버가 능동적으로 쌓는다. 아무도 화면을 보지 않아도 남아야 한다

### 3. 시그널 전이 기록

장중 상태 변화를 이벤트로 남긴다. 화면을 안 보던 시간의 흐름을 되짚기 위한 것이다.

| 대상 | 시그널 | 의미 |
|------|--------|------|
| 종목 | `VOLUME_SPIKE` | 1분 거래대금 배율이 임계를 처음 넘김 |
| 시장 | `NET_BUY_LEVEL` | 투자자 누적 순매수가 단계(조/천억)를 넘음 |
| 시장 | `NET_FLOW_TURN` | 누적 순매수가 정점에서 되돌려 방향이 꺾임 |
| 시장 | `MA_REBOUND` / `MA_BREAKDOWN` | 지수 5분봉 20이평 반등·이탈 (정규장만) |

- 같은 종목·같은 타입은 **쿨다운**(기본 3분)으로 중복 적재를 막는다. 프리마켓 출렁임이 실제 문제였다
- 같은 날 같은 순매수 단계는 재시작 후에도 다시 울리지 않는다
- 방문자에게는 등락률 0% 이상 최신 3건만 보여준다. **자르는 일은 서버가 한다**(브라우저에 도착하면 읽힌다)

### 4. 눌림·돌파

후보를 최근 3거래일 고가(돌파선)·저가(눌림선) 기준으로 본다. 선에서 3% 이내인 종목만, 가까운 순으로 보여준다. 방문자에게는 상위 3개만 보여준다.

### 5. 시황

| 항목 | 내용 |
|------|------|
| 지수 | 코스피 / 코스닥 / 나스닥 — 현재가, 분봉·일봉 |
| 선물 | 코스피200·코스닥150 선물, 야간 선물, 나스닥 선물 |
| 투자자 수급 | 외국인 / 기관 / 개인 — 일별·세션별, 현물과 선물 |
| 매크로 | 원달러 환율, WTI, VIX, 미국 10년물 |
| 휴장 | 국내·미국 휴장 배너 |

- 세션별 수급은 **당일 누적 스냅샷의 경계 diff**로 계산한다. 증권사가 세션별 값을 주지 않기 때문이다. 스냅샷이 없던 과거는 소급할 수 없다
- 지수·선물 시세와 차트는 공개한다. 어디서나 구할 수 있는 정보다. **투자자별 수급은 이 서비스가 가공한 값이라 로그인 뒤에 둔다**

### 6. 가입과 의견

- 구글 로그인(OAuth). 가입자는 구글 계정 식별자·이메일·가입 시각·마지막 로그인 시각만 남긴다
- 가입자는 서비스 안에서 의견을 남길 수 있다(500자). 알림은 운영 측 관측 도구가 이 기록을 보고 보낸다

## 비기능 요구사항

### 데이터 신선도

화면별로 갱신 주기를 다르게 둔다. 모든 화면을 같은 주기로 갱신하면 증권사 API 호출 한도를 넘긴다.

| 데이터 | 주기 |
|--------|------|
| 시그널 로그, 눌림·돌파 | 5초 |
| 주도주 후보·첫 화면 주도주 | 10초 |
| 지수·선물·1분 차트 | 30초 |
| 타임라인(당일), 수급 | 60초 |
| 종목 마스터 | 1일 (07:40, NXT 프리마켓 전) |

- 실시간 푸시(WebSocket/STOMP)는 쓰지 않는다. 도입했다가 연결 상태 관리 비용이 이득보다 커서 걷어냈다
- 화면에 포커스가 없어도 폴링은 계속한다 (듀얼 모니터에서 보기만 하는 창)

### 방문자 수와 무관한 브로커 부하

- 방문자가 늘어도 **브로커 호출은 늘지 않아야 한다.** 같은 데이터는 서버가 한 번 받아 모두에게 나눠준다
- 증권사별 호출 한도는 **어댑터 레벨의 공유 리미터**로 통제한다 (키움·KIS 조회 초당 5건)
- 한도에 닿으면 거부하지 않고 기다린다. 폴러가 죽는 것보다 늦는 게 낫다
- 특정 브로커가 응답하지 않아도 다른 화면은 살아 있어야 한다
- 브로커 토큰 발급은 희소 자원이다. 재기동이 발급을 소비하면 안 된다

### 공개 서비스로서

- API는 **기본 차단**이다. 공개 허용목록에 없는 경로는 로그인을 요구한다. 빠뜨리면 노출이 아니라 불편으로 끝나게 한다
- 저장소는 언제 공개해도 안전해야 한다 (`.claude/rules/security.md`)
- 검색 노출을 위해 경로별 정적 HTML과 sitemap을 빌드 때 만든다

### 운영

- 앱 인스턴스 1대 + 관리형 DB + 관측 전용 VM
- 실계좌 조회만 쓰고 모의투자 환경은 두지 않는다
- 4개 데이터 소스를 한 인스턴스가 모두 호출한다

## 범위 밖

명시적으로 하지 않는 것들이다.

- **주문·체결·잔고 조회** — 매매는 사용자가 HTS/MTS에서 직접
- **매매 신호에 따른 자동 실행** — 시스템은 전시만
- **백테스트·시뮬레이션**
- **수익률·실적 집계** — 시스템이 주문을 모르므로 계산할 수 없음
- **사용자별 데이터** (관심종목·메모·알림 설정) — `user_id` 기반 데이터 모델이 없다. 017에서 의도적으로 기능을 제거했다
- **권한 등급·유료 구분**
- **투자 자문·종목 추천** — 필터 통과는 "볼 만하다"는 뜻이지 매수 권유가 아니다
