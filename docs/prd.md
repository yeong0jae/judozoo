# PRD: 주도주 매매 판단 보조 시스템

## 개요

단타 매매 판단에 필요한 데이터를 여러 소스에서 모아 **가공·전시**하는 시스템.

사용자는 이 화면들을 보고 "지금 무엇을 볼 것인가"를 판단한다. **주문은 시스템이 내지 않는다.** 매수·매도는 사용자가 증권사 HTS/MTS에서 직접 실행한다.

> **이력**: 초기에는 자동 매매 시스템으로 출발했다(명령 접수 → 자동 주문 → 실적 리포트). 이후 "룰이 사람의 판단을 대체하기 어렵다"는 결론으로 **의사결정 보조**로 전환했고, 주문·체결 관련 코드는 전부 제거했다. 과거 설계는 [`plan.md`](./plan.md)의 폐기 섹션과 `tasks/000` ~ `tasks/013`에 이력으로 남아 있다.

---

## 해결하려는 문제

장중에 판단 근거가 되는 데이터는 여러 곳에 흩어져 있다.

- 거래대금 상위, 등락률, 분봉 거래대금 급증 — HTS 조건검색
- 투자자·프로그램 수급 — 별도 화면
- 선물·해외 지수·환율 — 또 다른 창
- 뉴스·이슈 — 브라우저

장중에 이걸 창 옮겨 다니며 조합하면 **판단 시점을 놓친다.** 이 시스템은 흩어진 데이터를 한 화면에 정렬해 그 시간을 없애는 것이 목적이다.

## 기능 요구사항

### 1. 주도주 후보 선정

당일 거래 종목에서 **필터 체인**을 통과한 종목만 후보로 남긴다. 각 필터는 독립적이고 순서에 의존하지 않는다.

| 필터 | 기준 (기본값) |
|------|--------------|
| 시가총액 | 3,000억원 이상 |
| 거래대금 순위 | 상위 35위 이내 |
| 당일 등락률 | +7% 이상 |
| 고가 대비 위치 | 60봉 고가 대비 -5% 이내 |
| 1분봉 거래대금 증가율 | 500% 이상 |
| 1분봉 거래대금 | 50억원 이상 |
| 1분봉 등락률 | 4% 이하 |
| 프로그램 순매수 | -100억원 이상 |
| 전일 종가 대비 | +25% 이하 |
| 시초가 대비 | +7% 이하 |
| 시가 위 | 현재가 > 시가 |
| ETF 제외 | ETF/ETN 제외 |
| SPAC 제외 | 스팩 제외 |

- 기준값은 설정(`application.yaml`)으로 조정 가능해야 한다
- 각 종목이 **어느 필터에서 탈락했는지** 확인할 수 있어야 한다
- 상한선(전일 종가 +25%, 시초가 +7%)의 목적은 "이미 다 간 종목"을 거르는 것이다

### 2. 시그널 전이 기록

장중 종목 상태 변화를 이벤트로 남긴다. 사용자가 화면을 안 보고 있던 시간의 흐름을 되짚기 위한 것이다.

| 시그널 | 의미 |
|--------|------|
| `BREAKOUT` | 돌파 |
| `BREAKOUT_IMMINENT` | 돌파 임박 |
| `VOLUME_SPIKE` | 거래량 스파이크 |
| `MA20_CROSS` | 20이평 돌파 |

시장 단위 시그널도 함께 기록한다.

| 시그널 | 의미 |
|--------|------|
| `NET_BUY_LEVEL` | 투자자 순매수 단계 전이 (조/천억 단위) |
| `NET_FLOW_TURN` | 순매수 흐름 전환 |
| `MA20_REBOUND` / `MA20_BREAKDOWN` | 지수 5분봉 20이평 반등·이탈 |

- 같은 종목·같은 타입은 **쿨다운**(기본 3분)을 둬 중복 적재를 막는다
- 프리마켓 출렁임으로 인한 중복이 실제 문제였고, 쿨다운은 그 대응이다

### 3. 시황 데이터

| 항목 | 내용 |
|------|------|
| 지수 | 코스피 / 코스닥 — 현재가, 분봉 |
| 선물 | 코스피200·코스닥150 선물, 야간 선물, 나스닥 선물 |
| 투자자 수급 | 외국인 / 기관(세부 7종) / 개인 — 일별·세션별(오전/오후/막판) |
| 프로그램매매 | 차익 / 비차익 / 전체 — 일별·세션별 |
| 매크로 | 환율·유가 등 |

- 세션별 수급은 **당일 누적 스냅샷의 경계 diff**로 계산한다 (증권사가 세션별 값을 주지 않음)

### 4. 이슈 기록

일자별 이슈 메모를 직접 작성·수정·삭제한다. 자동 수집이 아니라 **사용자 입력**이다. 나중에 "그날 왜 이 종목이 갔는지"를 되짚는 용도.

### 5. 해외 주도주

미국 주식에도 같은 구조를 적용한다.

- 랭킹 조회, 종목 상세, 분봉·일봉

## 비기능 요구사항

### 데이터 신선도

화면별로 갱신 주기를 다르게 둔다. 모든 화면을 같은 주기로 갱신하면 증권사 API 호출 한도를 넘긴다.

| 데이터 | 주기 |
|--------|------|
| 시그널 로그, 돌파 현황 | 5초 |
| 지수·선물·수급 | 30초 |
| 프로그램매매 | 2분 |
| 종목 마스터 | 1일 (08:30) |

- **실시간 푸시(WebSocket/STOMP)는 쓰지 않는다.** 폴링으로 충분하고, 연결 상태 관리 비용이 이득보다 컸다
- 화면에 포커스가 없어도 폴링은 계속한다 (듀얼 모니터에서 보기만 하는 창 대응)

### 외부 API 제약

- 증권사별 호출 한도를 **어댑터 레벨에서 공유 리미터**로 통제한다 (키움 조회 초당 5건 등)
- 한도 초과 시 거부가 아니라 대기로 처리한다 — 폴러가 죽는 것보다 늦는 게 낫다
- 특정 브로커가 응답하지 않아도 다른 화면은 살아 있어야 한다

### 운영

- 단일 사용자·단일 인스턴스
- 실계좌 조회만 사용하며, 모의투자 환경은 두지 않는다
- 브로커별 환경 분기를 두지 않는다 — 4개 소스를 한 인스턴스가 모두 호출한다

## 범위 밖

명시적으로 하지 않는 것들이다.

- **주문·체결·잔고 조회** — 매매는 사용자가 HTS/MTS에서 직접
- **매매 신호에 따른 자동 실행** — 시스템은 전시만
- **백테스트·시뮬레이션**
- **수익률·실적 집계** — 시스템이 주문을 모르므로 계산 불가
- **다중 사용자·인증**
- **투자 자문·종목 추천** — 필터 통과는 "볼 만하다"는 뜻이지 매수 권유가 아니다
