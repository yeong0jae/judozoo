# 개발 계획

## 현재 상태

이 프로젝트는 **자동 매매 시스템으로 출발했다가 매매 판단 보조 시스템으로 전환**했다. 아래 Phase 0~11은 자동매매 시절의 계획이며, 해당 코드는 전부 제거됐다. 지금 살아 있는 것은 Phase 12(leadingstock)와 그 이후 확장이다.

전환 이유는 단순하다. 룰 기반 자동 실행이 사람의 판단을 대체하지 못했다. 대신 **판단에 필요한 데이터를 한 화면에 모으는 쪽**이 실제로 쓸모가 있었다.

전환에 따른 제거 내역:

- `trading` 피처 전체 (매매 사이클 / 시그널 / 주문 / 체결 / 상태머신)
- `report`(실적 집계), `account`(잔고) 피처 — 주문을 모르면 계산할 수 없음
- 브로커 주문 클라이언트 (`KiwoomTradingClient` 등)와 KIS 주문 엔드포인트
- STOMP 실시간 푸시 — 조회 전용 화면에서 폴링 대비 이득 없음
- `vts`(모의투자) 프로파일 — 실계좌 조회만 사용

현재 시스템의 정의는 [PRD](./prd.md)와 [SPEC](./spec.md)을 참고한다.

---

## 전환 이후 작업

Phase 단위로 관리하지 않는다. 화면·데이터 소스 단위로 필요할 때 추가하는 방식으로 진행 중이다. 지금까지 붙은 것들:

- **주도주 후보 조회** — 필터 체인 12종, 필터별 탈락 사유 노출
- **주도주 실시간 로그** — 종목·시장 시그널 전이 기록 (쿨다운으로 중복 억제)
- **주도주 돌파 현황** — 감시 풀의 돌파 근접도
- **시황 분석** — 지수 / 선물(야간·나스닥 포함) / 투자자 수급 / 매크로
- **이슈** — 일자별 메모 CRUD
- **해외 주도주** — 미국 랭킹·상세·분봉 (KIS + 야후)
- **데이터 소스 확장** — 키움 / 토스 / 야후 어댑터 추가

---

## 원칙

1. **도메인은 순수하게** — 필터·판정 로직에 프레임워크·시간·HTTP 의존을 두지 않는다. 그래야 단위 테스트로 닫힌다
2. **외부 API 함정은 어댑터에서 흡수** — 부호·시각 오프셋·거래소 코드 문제를 화면까지 올려보내지 않는다
3. **호출 한도는 공유 리미터로** — 폴러가 늘어날 때마다 한도를 다시 계산하지 않아도 되게
4. **추측으로 API를 다루지 않는다** — 브로커 응답 형식이 불확실하면 문서를 확인하고 진행
